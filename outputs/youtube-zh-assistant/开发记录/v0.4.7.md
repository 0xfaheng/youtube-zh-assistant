# v0.4.7 开发记录

## 版本信息

- 升级时间：2026-10-06T10:08:23+08:00（Asia/Shanghai）；前版本0.4.6，新版本0.4.7。
- 开发目标：降低无字幕视频手动采音后的中文字幕延迟，让短片识别完成后尽快送译，并控制持续播放时的字幕积压。
- 实际模型分工：当前 Codex 主代理独立完成诊断、实现、测试与交付核验；未调用子代理，未升级 Astra。主代理具体型号无法由工具独立确认，没有将默认配置当作实际调用证明。真实翻译沿用用户现有账号配置，请求 gpt-6-luna / high / Fast；服务返回请求档位，没有可独立核验的实际模型路由标识。

## 改动内容

- 根因：旧采音每7秒一片，识别与翻译共用串行队列；完整语句模式在识别后还等待句尾或后文，翻译和显示积压会继续增加延迟。
- `extension/audio-processor.js`：连续语音最长约2秒提交；已采集至少约0.8秒且出现约0.3秒停顿时提前提交。跳过前导静音，保持跨分片PCM样本和多声道混音；提交实际样本长度。
- `extension/offscreen.js`：音频请求携带实际片长及采集时间；维持每代次最多一个在途识别请求，繁忙时跳过新音频，停止释放采集资源。
- `server/app.mjs`：识别、预热与释放使用独立有界音频队列；本机识别仍串行，防止同一GPU同时执行多个识别任务，但下一片识别可与上一批翻译同时进行。待处理计数合并两队列。
- `extension/background.js`：两种采音模式均先识别、不在识别请求中等待翻译，返回低延迟标记；按真实片长、采集间隔与倍速计算时间，拒绝非法元数据及超过3秒的旧音频。保留旧调用无元数据时的兼容路径。
- `extension/semantic.js`：低延迟音频即刻送译，不额外等待句号；完整语句模式使用已有上下文整理短句，逐片模式直接翻译。真实重复发言可再次送译。慢翻译保留最近约8秒待译文字，限制排队显示预算约8秒、单段约2–6秒，视频时间落后超过20秒的旧结果清除。被跳过的文字不计入原有音频片跳过计数。
- `extension/content.js`、`extension/generic.js`：两种显示模式均衔接延后翻译结果，保持停用、跳转及代次隔离。`extension/popup.js` 更新低延迟说明。保留0.4.6全部语义断行修复。
- `extension/tests/audio.test.cjs`、`background.test.cjs`、`content.test.cjs`、`generic.test.cjs`、`semantic.test.cjs` 和 `server/tests/semantic.test.mjs` 增加分片、立即送译、慢翻译及并行队列行为测试，共新增10项。
- 同步 `package.json`、`extension/manifest.json`、`server/app.mjs`、`web/index.html`、README当前版本；更新 CHANGELOG、开发记录索引，新增本轮基线、浏览器、真实识别翻译对比和运行状态验证脚本。
- 使用现有 `stop.ps1` 与 `start.ps1 -NoBrowser` 重启本机服务；配对、配置与密钥哈希保留，没有操作或重启用户日常Chrome。
